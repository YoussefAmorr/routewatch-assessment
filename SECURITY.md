# RouteWatch security and reliability

This prototype screens public airport/weather evidence. It has no payment features. Mission Control explicitly saves itinerary labels, optional employee references, assignments, notes, decisions, assessments, subscriptions and alerts in SQLite locally or D1 when deployed. Local mode is one loopback-only administrator; hosted operations require verified Cloudflare Access identity and configured organization membership. Optional Resend credentials stay in server environment configuration. Trip details are visible to the browser and providers receiving endpoint/time forecast queries. The browser downloads third-party map and AI assets.

## Implemented controls

- Server validation accepts supported three-letter IATA codes, distinct endpoints, valid airport-local dates/times, a bounded forecast horizon, and one to four chronologically connected legs.
- JSON API bodies are limited to 16 KB, including streamed bodies. The local Node adapter also enforces this limit before buffering. API query parameters, cross-origin browser requests, and unsupported content types are rejected.
- Fixed HTTPS provider allowlists; redirects are rejected. Upstream calls have a 20-second timeout, 4 MB response limit, and a 32-call per-instance concurrency ceiling. No request accepts a provider URL. Resend delivery and Access key retrieval use fixed or configuration-validated HTTPS endpoints.
- Assessment requests are limited to 20 per minute per connecting IP on Cloudflare, with eight active response streams per instance. Local execution shares one bucket. Limits are in memory and are not global across instances. Streaming cancellation releases the response slot; already-started upstream requests may continue until their bounded timeout.
- Source text is escaped before HTML insertion. Provider evidence links are restricted to trusted HTTPS hosts. Imported snapshots have size, nesting, source URL, numeric forecast, airport, and AI-field checks. Shared snapshots are unverified supplied records, not signed evidence.
- Responses include a nonce-based script CSP, framing denial, nosniff, no-referrer, restrictive permissions and no-store. HTTPS responses include HSTS. CSP permits the specific CDN/model/font hosts and WebAssembly compilation; it does not permit general JavaScript unsafe-eval. Inline styles remain permitted because the current charts and UI use embedded and dynamically assigned styles.
- External new-tab links include noopener noreferrer. Provider failures and unexpected request failures return generic messages rather than stack traces or internal paths.
- Browser history saving is opt-in and limited to 20 records. Saving to Mission Control is a separate explicit action and creates persistent server-side records. Users can clear it. Shared URLs are not encrypted: share only with intended recipients. No request bodies or travel routes are intentionally logged by the app.
- Hosted operations validate signed Access JWTs (RS256, issuer, audience and expiry). Every operations read/write scopes records to the authenticated organization. Viewer mutations are forbidden. Membership comes from trusted server configuration, never submitted identity headers alone.
- Workflows use optimistic version checks and transactional audit insertion; audit rows cannot be edited or deleted by application endpoints. Notes and trip labels are escaped in dialogs.
- At most two operations checks run concurrently per instance. Job tokens prevent duplicate queue processing; delivery leases and Resend idempotency keys reduce duplicate sends. Email recipients must belong to the configured organization in hosted mode. Subscriptions are explicit and removable.
- Local SQLite files use restrictive filesystem permissions; .data and .env files are excluded from Git and source packages. Assessment records retain the newest 40 per trip plus captures linked to alerts. Audit records persist; define an administrative retention/purge policy before collecting real employee data.
- Structured logs contain event names, random request IDs and result/error categories, without intentionally logging employee names, routes, notes, email addresses, tokens or keys.
- AI classifications remain advisory: they cannot change the deterministic risk level, execute code, or take operational actions.

## Verification

Run `npm run check` for route/date/DST validation, source outages, streaming, airport coverage, recorded evidence and security cases. `scripts/check-security.mjs` tests malformed JSON/routes, XSS-like input, past/far-future dates, oversized bodies, origin/content-type policy, nonce headers, opt-in history, error redaction and rate limiting. Live regressions also retrieve actual FAA, NWS and Open-Meteo data. Run `npm run build` and `npm run validate` before packaging.

There are no installed npm runtime dependencies to audit. Browser dependencies are version-pinned CDN imports (Transformers.js 3.7.2, d3-geo 3.1.1, topojson-client 3.1.0 and us-atlas 3.0.1); model assets are fetched from Hugging Face. `npm audit` cannot assess CDN/model assets. These have not received a comprehensive supply-chain or vulnerability audit. Consider bundling assets and pinning model revisions before production.

## Deployment and remaining boundaries

The development server binds to 127.0.0.1 over HTTP. Use HTTPS for hosted access, keep hosting credentials outside source control, and use the platform's access controls if the tool should be private. Hosted identity validation and organization permissions are implemented but no live Cloudflare Access application, D1 database or queue has been provisioned. See OPERATIONS-GUIDE.md for the deployment template. Configure shared edge rate limits before exposing the service broadly; an in-memory Worker limit is insufficient for distributed abuse. Operations mutations are additionally limited to 60 per minute per member per instance. No CORS access is enabled; frontend and API must share an origin. Enforce equivalent headers and size limits if a reverse proxy overrides application responses.

Source freshness is checked where available; current advisories are not future flight predictions. Forecast uncertainty and missing-source states remain visible. Snapshot validation does not authenticate its author. Cryptographic authentication and role/isolation tests use generated test keys, not a live managed-provider account. Actual email delivery has not been tested without user credentials. No penetration test, full secret scan, or infrastructure review has been performed. To report a vulnerability, contact the project owner privately with minimal reproduction steps; do not include credentials or another person's travel details.
